# 基于 PYNQ 的实时音频均衡与频谱分析系统

本工程参加 FPGA 创新设计竞赛 AMD 赛道，目标是在单片可编程片上系统上实现一套完整、可复现的实时音频处理平台。

## 一、项目简介

音频均衡与频谱分析是音频工程中最常用的两项基础功能，前者按频点调整增益以修正音色，后者将信号映射到频域以观察其频率构成。本作品基于 AMD Zynq-7020 可编程片上系统实现了一套集两项功能于一体的实时音频处理系统，将数值运算全部下沉至可编程逻辑中执行，使用者只需在浏览器中即可完成交互。系统的硬件通路依次由直接内存访问控制器、六十四阶有限冲激响应均衡器与一千零二十四点快速傅里叶变换处理器构成，音频数据以帧为单位在硬件中闭环流动，处理期间中央处理器不参与任何运算，仅承担任务调度与人机交互职责。实测结果表明，系统对一千零二十四点单帧的处理时延为二点一毫秒，等效吞吐率约零点四九兆采样点每秒；低通工作模式下通带衰减仅零点四分贝，阻带抑制达到五十四点一分贝，频谱镜像泄漏低于负五十八分贝。全部逻辑仅占用芯片查找表的百分之十四点三五，时序裕量六点四八七纳秒，可稳定运行于一百兆赫兹。本工程的全部源代码、比特流与测试脚本均已开源，可供教学演示与二次开发自由复现。

## 二、硬件简介

系统的硬件载体是 PYNQ-Z2 开发板，其核心器件为 AMD Zynq-7020，完整型号 XC7Z020-1CLG400。Zynq 系列属于可编程片上系统，即在单颗芯片内同时集成处理系统与可编程逻辑两大部分：处理系统部分为双核 ARM Cortex-A9 处理器，运行 Linux 操作系统，负责软件层面的调度、通信与可视化；可编程逻辑部分等价于一片 Artix-7 架构的现场可编程门阵列，内含约五万三千个查找表、十万余个触发器、一百四十个三十六千比特块随机存取存储器以及二百二十个数字信号处理单元。查找表与触发器是构成时序与组合逻辑的基本单元；块随机存取存储器用于缓存帧数据与滤波系数；数字信号处理单元内部集成乘法器与累加器，是滤波器乘加运算的物理载体。

音频的采集与回放由板载 ADAU1761 音频编解码器完成。编解码器的作用是将麦克风或线路输入的模拟声压信号转换为数字采样序列，并在输出方向执行相反的转换以驱动耳机或音箱。本系统将采样率设定为四十八千赫兹、位深十六比特，即每秒对声压进行四万八千次均匀采样，每次采样的幅度分辨率为十六比特，对应的动态范围约九十六分贝，足以覆盖一般语音与音乐信号。

数据通路在可编程逻辑中以知识产权核互联的方式构建，整体框图与源码随工程一并给出。直接内存访问控制器承担内存与逻辑之间的数据搬运，其存储器到流通道将待处理帧送往逻辑，流通道到存储器通道将处理结果写回内存，整个搬运过程无需中央处理器逐字介入。均衡器核由 Vitis HLS 高级综合工具从 C++ 描述自动生成，核内包含一百二十八路并行乘加结构，系数经由 AXI-Lite 轻量级配置总线写入，基地址为十六进制的 0x40000000，自十六进制偏移 0x80 处起共布置三十二个十六比特增益寄存器，软件以单条总线写操作即可在运行期改写任意频点的增益。

变换核采用 XFFT 第九版，一千零二十四点、十六比特字长、缩放工作模式，其配置通道由常量核固化为十六进制值 0x0555，含义为正向变换配合逐级的缩放计划，从硬件层面消除了软件误配导致数据溢出回绕的可能。

## 三、算法简介

数字音频处理的本质是对采样序列施加确定的数学变换。本系统的算法链条由分帧、有限冲激响应滤波与离散傅里叶变换三个环节顺序构成。

有限冲激响应滤波器简称 FIR 滤波器，其输出是输入序列与一组固定系数的离散卷积，每个输出样点等于最近若干个输入样点与对应系数的加权和。本系统的均衡器为六十四阶复数结构，加权窗口覆盖最近六十四个复数样点，三十二个增益寄存器各对应窗内一项系数，写入不同系数即可得到低通、高通或全通等幅频特性。系数采用 Q15 定点格式表示，即以十六比特有符号整数代表归一化小数，既保证了十六比特数据通路下的运算精度，又使全部乘加在整型逻辑中完成，无需消耗浮点资源。借助高级综合工具的循环展开指令，六十四阶复数卷积被展开为一百二十八路并行乘加，单个时钟周期即可产出一个输出样点。

快速傅里叶变换是离散傅里叶变换的快速算法，用于将时域采样序列映射为频域的幅度分布，是频谱分析的核心工具。本系统采用一千零二十四点变换，每次处理由一千零二十四个样点构成的一帧，频率分辨率为采样率除以一千零二十四，约四十六点九赫兹。变换核工作在缩放模式，每级蝶形运算后右移一位以抑制字长增长带来的溢出，代价是输出幅度按级数整体缩小。需要说明的是，本设计变换核的输出按位反转序排列，即第 j 个输出对应自然顺序中将 j 的十位二进制表示倒序重排后所得的频点，软件在计算幅度前须按十位二进制倒序重新排列。幅度谱由实部与虚部平方和的平方根得到，据此可绘制频谱并提取峰值位置，功能验证正是基于这一原理构造单峰与双峰两种判据。

系统在软硬件之间保持清晰分工：处理器只负责合成测试信号、写入系数、发起传输与绘制结果，全部数值运算在可编程逻辑中流水完成，因此处理时延确定且处理器占用为零。这一架构是系统区别于通用软件实现的关键，软件频谱分析受制于操作系统调度，时延抖动通常在毫秒量级，而本系统的硬件通路时延稳定保持在二点一毫秒。

## 四、操作说明

复现本工程需要 PYNQ-Z2 开发板一块、烧录 PYNQ 2.7 版镜像的 SD 卡、Vivado 与 Vitis HLS 2020.2 版工具链，以及一台经 USB 与串口连接板卡的计算机。

第一步，将 bitstream 目录下的比特流文件 audio_fir_fft_v6.bit 与配套硬件描述文件 audio_fir_fft_v6.hwh 上传至板卡的 /home/xilinx 目录，并将 pynq 目录下的全部脚本一并上传。传输可以经以太网在 Jupyter 文件界面完成，也可以通过串口以 base64 分块方式完成，本仓库附带的桌面辅助脚本实现了后一种方式并附带校验。

第二步，板卡上电，等待约九十秒至启动完成，以 xilinx 为用户名登录串口控制台，密码同为 xilinx。

第三步，依次执行两条功能验证命令，即 sudo python3 /home/xilinx/fft_check.py A 与 sudo python3 /home/xilinx/fft_check.py B。前者合成单音复数信号，期望频谱在第一百个频点出现单峰；后者合成实部单音信号，期望在第一百与第九百二十四个频点出现幅度近似相等的对称双峰。两条命令均输出 PASS 即表明数据通路功能正确。

第四步，执行 sudo python3 /home/xilinx/filter_demo.py ap 与 sudo python3 /home/xilinx/filter_demo.py lp，分别对应全通与低通两组系数，比较两次输出的频谱数据即可观察滤波效果；执行 sudo python3 /home/xilinx/accel_test.py 可复现单帧二点一毫秒的时延实测。

如需重建硬件工程，在 Vitis HLS 中综合 hls 目录下的 fir_eq.cpp 并导出知识产权核，随后在 Vivado 中导入 vivado 目录下的 Block Design 源文件与全部 IP 配置，执行生成比特流即可得到等价结果。

## 五、注意事项

串口控制台默认波特率为115200，仓库附带的上传脚本在传输前会将其提升至460800，板卡重启后波特率自动复位，若终端出现乱码需重新执行提速步骤。板端脚本需要管理员权限，sudo 密码为 xilinx。直接内存访问的单次传输长度不宜过大，实测单次提交六十四帧以上的块传输可能使发送通道挂起，如遇挂起可中断进程并重启板卡，常规的按帧循环传输不受影响。比特流与硬件描述文件必须配套使用，任一更换后需同步更新，否则 PYNQ 框架无法正确识别寄存器映射。复音判据依赖位反转序到自然序的重排，若修改变换核的输出顺序选项，软件中的重排步骤须同步调整。最后，测试脚本运行在 PYNQ 2.7 版本之上，更高版本的框架尚未验证，升级前请先行确认驱动接口的兼容性。
